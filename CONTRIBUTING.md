# Contributing

Describe the problem, expected behavior and a reproducible example before proposing a substantial change. Keep changes focused and document any changes to launch commands, scene geometry or inventory accounting.

Run the lightweight checks from [setup](docs/SETUP.md). For ROS or GPU changes, report the environment, exact command and whether the test used the full scene or a reduced scene. Do not present offline geometry tests as proof of collision-free navigation.

Do not commit downloaded models, operational databases, credentials, generated maps or external workspaces. Preserve upstream asset attribution and vendored licenses. Include screenshots for UI changes and clearly label demo data.
